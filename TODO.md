## Rendering

4. **A jump to a found point is slow**: the viewer zooms to z17 at the hit, and z17 tiles are rarely cached (`precache` stops at z12 for GoogleMapsCompatible), so every tile of the view is rendered on request. Related: the cold z13-16 tiles not measured on `de` (item 1).
5. **Icons at tile seams are dropped.** Each tile is rendered on its own with its own collision detection. A symbol near a seam lies in both tiles' buffers; one tile placed it and the other dropped it in a collision only it saw, so the seam showed half an icon. `allow-overlap` drew every icon but overlapping each other and their labels; `avoid-edges` did nothing until the Map buffer was set to 0 and the buffer moved to the layers (`DESIGN.md` "Symbols at tile seams"). Now a symbol that would cross a seam is drawn in neither tile: a stitched 4×3 block of z18 tiles in Vaduz had no cut symbol and four missing icons (a parking, a bus stop, a fuel station, one more). Street labels drop at seams too, but repeat along the line. Which POIs are lost depends on where the grid falls.
    **Cure: metatiling** -- render e.g. 4×4 or 8×8 tiles as one image, decide collisions once, and cut it. Symbols are then only lost at metatile edges, which still need `avoid-edges`. Touches `renderer/core.py`, `renderer/cache.py` (write all tiles of a metatile) and the pre-cache, and makes a cache miss cost a whole metatile. The alternative discussed: thin POIs deterministically in SQL (one per grid cell per zoom) and draw them with `allow-overlap`.
6. **Shields for motorways and major roads: road refs as boxes**, as osm-carto draws them: a ref ("A 7", "B 76", "K 29") on a rectangle in the road's color with its casing as border. Mapnik draws no text background, so the style run would write one SVG per palette × road class × character count next to the icon set, the shield query adds `char_length(ref)`, and `shield` mode compiles to a line-placed `ShieldSymbolizer`. No re-import. Open: a road with several refs (`B 76;L 52` -- osm-carto stacks them), and the character width of Noto Sans Bold 9.
7. **`?v=` repeats after a restart.** The generation counter is per process, so with the cache on a restarted server reuses `?v=1` and a browser keeps its `immutable` tiles (`web/httpcache.py`).
8. **No HiDPI tiles.** Proposed: a 512 px render with Mapnik `scale_factor=2` at `/xyz/.../{y}@2x.png`, its own cache tree, the viewer choosing it when `devicePixelRatio > 1`. Unverified whether Mapnik corrects `!scale_denominator!` for the scale factor; if not, the bands would be read one zoom too fine.
9. **Labels on small objects start later** since `zoom_max` went from 18 to 21: the size test used to clamp at 18. On `li` some 1 500 labels moved off z18. Not reviewed whether that is wanted.
10. **An area and a node for the same feature** (a hospital mapped as both) can give two icons; the collision test usually drops one.
11. **Between an area's icon zoom and its icon label zoom** the object has no name: the area label stops where the icon starts, the icon's name starts later (a school at z17 on `max`). Accepted for now.
12. **Palettes.** In `dark`, `clr_label_minor` is shared by small places and area labels, so lightening one lightens both; secondary road names read grey without bold; ref shields keep an opaque 2 px halo. `light` and `hico` did not get the darker labels and soft halo `default` got. Noto's smaller x-height may want 10 px where 9 px is used. No `FontSet` for glyph fallback.
13. **Label `dy` under icons** and the marker size (27 px drops more POIs where they are dense) not reviewed.
14. **No style entries above z18** except house numbers at z19: roads, labels and icons keep their z18 size to z21.
15. **Vector tiles are not started**: `renderer/vector.py`, `build.py`, `archive.py`, `styles/mvt.yaml` (class → MVT layer and attributes), the MapLibre style generated from the same style files, a sprite from the same icon set, `/vector/*` and `/pmtiles/*`, and a `/pmtiles` block in the Caddyfile.
16. **TileJSON per theme**: `GET /xyz/{theme}.json`, a TileJSON 3.0.0 document (`tiles` with the caller's `?key=`, `minzoom`/`maxzoom`, `bounds`, `attribution`), linked from `/metadata` as `{"rel": "tilejson", "href": ".../xyz/{theme}.json", "templated": true}`. MapLibre and OpenLayers then need one URL per theme. Web Mercator only -- TileJSON cannot describe DE_EPSG_25832_ADV. Worth it once vector tiles exist, since MapLibre expects TileJSON for them.

## Import and model

21. **`osm_id` is not unique across OSM types**: a node and a way can share an id, and `id_object` can resolve to the wrong one. Typed ids (`n123`, `w456`, `r789`) in search responses are deferred; not checked whether the importer still knows the type.
22. **Many named objects are still "other"**: on `de_sh` 1 276, e.g. `boundary=marker` 328, `waterway=depth` 89, `waterway=fairway` 67, `railway=razed` 60, `boundary=postal_code` 43, `highway=proposed` 37, `amenity=small_vehicle_parking` 34, `landuse=village_green` 27, `amenity=lifeboat` 21. Also `place=county`, `province`, `municipality`: a county node does not merge with its Kreis ("Pinneberg" never returns the Kreis polygon).
23. **Mixed-tag objects get the class of whichever rule matches first**: some ferry terminals come out as `cls_poi_sights`, `cls_building` or `cls_landuse_industrial`.
24. **A mistyped class in a rule is only a warning** in `gen_classifier.py`, and its objects are silently not drawn. Proposed: an error, now that classes are few and hand-named.
25. **`building=no` is drawn as a building**: the `building=*` fallback matches it, and the rule language has no negation.
26. **The importance values are a first set**, not tuned against search results; `ranking.importance_weight` is (`parameters.yaml`). A station and a bus station are both 80, so for "Hauptbahnhof Kiel" the bus station "Hauptbahnhof" ties with the station "Kiel Hauptbahnhof" (item 45).
27. **Categories no rule assigns** (e.g. `cat_built_transport_stop_platform_buspoint` since the hand-written platform rules). Children that share a name with their parent but are different tags (Kiosk/Convenience store, Memorial/Monument, Fuel Shop/Fuel) are left in place.
28. **Unnamed categorised objects are not searchable** (a nameless playground), so a category browse returns named things only.
29. **Named objects no rule matches** have NULL importance and are still searchable. Decided without asking.
30. **Memory.** The areas pass ignores `location_store` (`with_areas()` without `with_locations(...)`), `with_areas()` buffers every relation's member ways with no filter, one worker process runs all passes and keeps its freed memory, `location_store` is a parameter and not a deployment option, and per-pass peak RSS is not logged. The memory prefix of the log lines reads `/proc/meminfo`, which is the host's, not a container limit's.
31. **Areas larger than `de`** (Europe): not feasible without the memory work above, file-backed location stores, and a chunked or SQL street merge. Estimated, not measured.
32. **The versioned default `serve_area: sh`** names an area that no longer exists (`app/config/options.yaml`).
33. **Unread settings**: `model/parameters.yaml`'s `precache` section (the depths are the `precache` option) and `streets.merge_by` (the merge is hard-coded); the `db.pool_size`, `db.pool_overflow` and `db.pool_timeout` options.
34. **`cls_ocean` is a literal in three places** (`renderer/styles.py`, `tools/gen_classifier.py`, `importer/postprocess.py`). Proposed: a hand-written rule for it.
35. **The import summary mislabels two counts**: `run.summary()` prints the places step's object-area and address-area link counts as search objects and addresses.
36. **The relation pre-pass logs nothing** until libosmium has skipped past all nodes and ways; on `de` it looks like a hang.
37. **Resuming an import from a step** (`--from <step>`). Needs a record of finished steps per schema, re-runnable steps, a refusal once `_street_ends` is dropped, and a check against mixed code versions.
38. **Water runs after the passes**, not beside them.
39. **An import competes with serving** for CPU, memory and `shared_buffers` on the same host.
40. **Updates are a full re-import.** `import_meta` keeps the replication position for a diff path if re-import time ever demands one.
41. **`places.levels` is German.** Another country needs its own list; a Land has an empty path.

## Search

42. **A street merged with a named crossing way disappears.** Kölner Straße in Düsseldorf south of the Hauptbahnhof (Oberbilk, ~51.209-51.217) is found by no mode, not even a click. The merge (`importer/postprocess.py` `merge_streets`) gives the merged row `min(e.category)` and `min(e.class)`, the alphabetically smallest of its ways, and drops a row whose category has importance 0. `_street_ends` takes every named `cls_road_*` way, importance 0 included (`importer/passes.py` `_search` checks importance only for unmerged rows). There the street is mapped with crossing ways carrying its name (way 1250537301, `highway=path + path=crossing + foot=designated + bicycle=designated` → `cat_built_roads_crossing_pathcrossing_bicyclefoot`, importance 0), which share end nodes with the carriageways; `cat_built_roads_crossing_…` sorts before `cat_built_roads_secondary`, so the whole component is dropped, and its ways have no rows of their own. The same `min()` gives any street merged with a named sidepath class `cls_road_path` and a path or cycleway category, which probably also keeps it out of `osm_street`. Found by reading the code against the OSM tags; not reproduced, no NRW import on the dev stack. Fix: keep importance-0 ways out of `_street_ends`; take the merged row's category and class from its most important way (importance, then road rank); a test on `li` that a road with a named crossing way keeps its street row and class. Then re-import and check on `de_nrw`.
43. **The point mode misses a house a few metres off.** Two points in Kiel, EPSG:3857: `[1128527.8753043748, 7231529.193837811]` (on the house number) finds the house, `[1128536.1697837499, 7231503.6866231235]` does not -- 27 map units away, about 16 m on the ground at 54.3° N, inside the default 50 m / 25 m radius. Not looked into: whether the radius is applied in map units or metres, and whether the house is reached only as an area containing the point.
44. **"lidl köln porz" is read wrongly**: `name_like_in_place (4) · name "lidl koeln" · place Porz`. "Köln" goes into the name instead of narrowing the place, so a Lidl in Porz is found only if its name contains "Köln". Wanted: name or brand "Lidl" in Porz, a district of Köln. Same root as item 52: a rule has one place, and a second place word has nowhere to go but the name.
45. **Stations**: "Hauptbahnhof Kiel" finds the station "Kiel Hauptbahnhof", tied with the bus station "Hauptbahnhof" (item 26). "Kiel Hbf" does not: "hbf" is not expanded like "str.", which needs the same change in the importer's normalisation and a re-import.
46. **"dom" is slow and ranks wrongly.** A short, common word that occurs in many names and compounds; which results lead, and which step costs the time, is not recorded. Probably a case of the tail in item 62.
47. **Named non-street lines are not merged**: a river of 40 ways is 40 hits, and "rhein" returns thousands. `search.merge_classes` (`model/parameters.yaml`, `[cls_road_*]`) is the switch; adding waterways and other named line classes is untried, and the merge itself is written for streets (`streets.merge_by` is unread, item 33).
49. **Roads with a `ref` and no `name` are not searchable.** On `de_sh` 3 931 of 3 964 motorway ways have no name, nor do most Landes- and Kreisstraßen, so a click on the A 7 returns no road and "A 7" finds nothing. Merging them per connected piece is too much on `de` (the A 7 would touch every municipality). Options: (a) `ref` as a fallback name, one row per way, never merged -- needs a flag, since the street merge takes every road row by name, and "A 7" returns thousands of ways on `de`; (b) the same rows, excluded from the text modes, so a click names the road; (c) leave it. (a) or (b) adds some 100 k rows on `de`. "Rastplatz on A7 near Neumünster" needs more: "A7" in the street dictionary normalised like "A 7", stop words like "on", "near", "an", "bei" (`phrase.STOP_WORDS` lacks them), and a rule category NEAR street NEAR place that looks the street up near the place.
50. **Duplicate results**: "Autohof Neumünster" and "Aalbek-West" each come back twice, probably a node and an area. Not looked into.
51. **No standard German abbreviations**: "Bonn Hbf" does not find "Bonn Hauptbahnhof", nor "Kita" "Kindertagesstätte" (likewise "Bf", "Hbf.", "FH", "Uni", "KH"). Only "Str." is expanded, and only for street names (`lib/text.py`). An abbreviation list could be applied in normalisation, on both sides and frozen by `test_text.py`, or expanded on the query side only; not decided.
52. **Nested places** ("Kiel Mettenhof"): a rule has one `query.place`; the coarser name cannot narrow which same-named finer place is meant. See item 44.
53. **The address mode's city matches any place on the path**, so a Land or Kreis as the city matches every Hauptstraße 5 inside it. Proposed: municipality level and below. And a node-only village as the city matches only through `addr:city`.
54. **A long line collects every place it touches.** "Planung Stadtbahn Kiel" lists up to 14 places for its longest row, 15.8 km. A point or line is linked to every area it intersects, a polygon needs `places.area_share` of itself inside. Proposed: the same share by length for lines -- a street crossing a border roughly in half stays in both municipalities, one that pokes 20 m over it is in its own only. It reverses `test_a_street_across_a_border_lies_in_both_municipalities`, and a street mostly in Kronshagen with its last 50 m in Kiel would no longer be found under Kiel. Related: a polygon straddling a border has both branches on its path, and the flat list sorted by level interleaves them ("Aalbek-West": Neumünster > Kreis Rendsburg-Eckernförde > Wasbek > Gartenstadt).
55. **`location NEAR query.place` only for places without a border**: a Dorfstraße just across a village's border is missed.
56. **An Amt (admin level 7) as the place finds nothing**: it is on no path and not tested by containment.
57. **"Hauptstraße" is iD's term for primary roads**, so "hauptstrasse bargteheide" (no Hauptstraße there) leads with Bargteheide's primary roads. Reading a street-dictionary word as a name only was tried and withdrawn: it also took "dorf", "feld", "insel" away as categories.
58. **"Restaurant Maxim Kiel"** -- no Maxim in Kiel -- falls to `name_like_in_place` and returns restaurants called "... Restaurant".
59. **House-number ranges match their first number only**: "25-27" is stored as 25.
60. **POIs without `addr:*` inside an addressed building** are not linked to it, so the address mode returns a bare address.
61. **A category word matches names that carry it**: with no restaurant "Maksim" in Kiel, "Restaurant Maksim Kiel" returns "IKEA Restaurant", "Citti-Restaurant" (`name_like_in_place`, 0.51-0.55), equally weak, so `phrase_strict_best_share` keeps them all.
62. **The tail on `de`**: "Restaurant Wilstedt Siedlung", "Apotheke Königsallee Düsseldorf", "Restaurant Maxim Köln", "Restaurant" with no view take 0.8-1.0 s. Not re-measured since.
63. **`near_street_distance_m` (100) and `near_street_group_m` (1 000) are guesses.** "Bäckerei Hauptstraße" near Kiel returns only bakeries whose own address is on some Hauptstraße.
64. **Point mode**: `limit` cuts the concatenated list, so areas are dropped first, and `total` counts the address's object even when it falls beyond `limit`.
65. **Unknown request fields are ignored**: a client still sending `q` gets a 422 in the name and phrase modes and silently nothing in the address and point modes.
66. **An address hit with an object** has the id `a<id>`, not the object's `o<id>`, because one building can carry two addresses. Not confirmed with the user.
67. **The object lookup for address hits** (one more query per page) is not measured.
69. **`osm_category_term.lang` has an interim rule**: the request's language first, then the longest match. A long term in one language loses to a short one in the other.
70. **Paging is `OFFSET`-based**; deep pages over a large result are linear.
71. **No spell correction and no synonyms** beyond the categories' terms. Abbreviations: item 51.

88. **Log lines of the other services carry two timestamps**: rsyslog's prefix and the service's own (postgres's `log_line_prefix`, pgbouncer's, Caddy's JSON `ts`). uvicorn's own lines in the app log have a format of their own (`INFO:     ...`), and `import.log` is still in `data/`, not `data/log/`.

91. **The API's texts are English only**; wanted in German and English, picked with `?lang=` as the landing page and the devtools do (`lib/i18n.py`, `lib/messages.yaml`). What remains: the `detail` of every `HTTPException` in `web/` (~20) and the `RequestError`s of `search/request.py` (31) -- which the devtools show as they come -- the WMTS Capabilities' `Title`/`Abstract`, and `/docs` (the OpenAPI title, description, route docstrings and field descriptions).
